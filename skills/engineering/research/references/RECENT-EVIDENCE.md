# Recent Evidence

Use this branch when the question depends on what changed recently or what people report. Official facts still need the source that owns them.

1. Resolve the topic's actual projects, people, and communities before retrieval. State the date window and distinguish publication date, event date, and retrieval date.
2. If `last30days` is available and suitable, use its installed instructions for preflight, health checks, query planning, execution, and saved evidence. Reuse a current run when it covers the question; do not require a rerun for unchanged facts.
3. If it is unavailable, use available search or source APIs and state the resulting coverage. Tool installation, cookie access, paid services, and publishing require the applicable authority; a research request alone does not establish it.
4. Read source outcomes. A completed search with zero relevant matches is different from a rate limit, expired authentication, skipped source, timeout, or parse failure. Report the latter as incomplete coverage.
5. Check relevance before engagement. Separate independent observations from reposts, quotations of the same announcement, and multiple accounts repeating one report. A handful of comments is directional evidence, not consensus.
6. Use primary documentation or code to verify technical claims surfaced by discussion. Label a bug report as a report until reproduction or maintainer evidence supports the claim.

The report records the window, channels actually searched, limitations that affect the answer, and pointers to retained raw results. A recent community scan supplements the evidence; it does not make older verified contracts obsolete.
