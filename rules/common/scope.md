# Scope

- Do what was asked. Do not refactor, rename, reformat, or "improve" code the
  request does not touch. Mention what you noticed instead.
- Match the conventions of the file you are editing, even where you would
  choose differently in new code.
- Clean up what your change made unused. Leave pre-existing dead code alone and
  mention it.
- Prefer the simplest change that solves the stated problem. Add an abstraction,
  option, or dependency only when a present need requires it.
- When the request is ambiguous in a way that changes the work, state your
  assumption or ask. When you disagree with the approach, say so once, then
  follow the user's decision.
- Ask before actions that are hard to undo or that reach outside the workspace:
  deleting data, publishing, deploying, or messaging people.
